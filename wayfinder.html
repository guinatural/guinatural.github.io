Wayfinder Cloud

Projeto de portfólio que explora uma arquitetura de governança AWS orientada a eventos para um cenário hipotético de saúde digital. Os tempos de detecção e os resultados de operação não foram medidos como SLA.

Contexto: VitaCore Health (cenário hipotético) Stack: AWS · Terraform · Python 3.12 Status: Projeto de portfólio em desenvolvimento; sem implantação produtiva declarada Repositório: github.com/guinatural/wayfinder-cloud ↗
Cenário hipotético de projeto
Exposição de dados em um ambiente de saúde

VitaCore Health é um cenário fictício usado para explorar controles contra exposição de dados sensíveis. Não representa um incidente, uma organização, uma sanção ou um resultado operacional real.

01

Arquitetura explorada

A arquitetura proposta usa AWS Config como motor de avaliação. No fluxo descrito, quando um recurso viola uma regra, o EventBridge encaminha o evento a uma Lambda para enriquecer e notificar o achado; uma remediação com guardrails é uma opção de desenho, não um resultado operacional verificado nesta página.

O desenho documenta registro de eventos e consulta via Athena, além do uso proposto de S3 Object Lock. A retenção e os controles efetivos dependem da configuração implantada e da política aplicável; esta página não declara conformidade legal.

03

Decisões de arquitetura (ADRs)

Cada decisão relevante tem um ADR. Não uso ADR como burocracia — uso para rastrear por que escolhi algo e quais alternativas descartei.

ADR-001
Terraform, não CDK
A decisão prioriza praticar e revisar diretamente os recursos declarados. A ferramenta escolhida depende do contexto e da familiaridade da equipe.
ADR-002
Event-driven, não polling agendado
O desenho orientado a eventos evita depender de varredura periódica. A latência e o custo reais dependem da implementação e precisam ser medidos.
ADR-003
S3 Object Lock COMPLIANCE (não GOVERNANCE)
A escolha do modo e do prazo de retenção deve ser validada conforme o tipo de documento e as obrigações aplicáveis; Object Lock não é, por si só, certificação de conformidade.
ADR-004
Remediação seletiva, não total
A remediação deve considerar reversibilidade e impacto no workload. O desenho favorece alertas quando uma mudança automática pode interromper um serviço.
ADR-005
VPC Endpoints, não NAT Gateway
VPC Endpoints podem manter chamadas a serviços AWS no caminho privado da VPC e reduzir dependência de NAT; a escolha depende dos requisitos e custos do ambiente.
ADR-009
IAM OIDC no CI/CD, não access keys
OIDC permite trocar credenciais estáticas por credenciais temporárias quando o workflow e as políticas são configurados corretamente.

06

O que aprendi construindo isso

  • 🔐IAM é parte central do desenho. Permissões excessivas ampliam o impacto de erros; o case inclui controles para revisar políticas com escopo amplo.
  • ⚡Event-driven é uma escolha de arquitetura, não uma promessa de latência. O case compara roteamento por eventos com varredura periódica; qualquer diferença de tempo ou custo precisa ser medida no ambiente alvo.
  • 🧪Testar código que chama AWS é difícil sem moto. Aprendi que dois handlers com o mesmo nome em sys.modules se sobrepõem. A solução com importlib.util.spec_from_file_location foi mais valiosa do que a feature em si.
  • 📄ADRs registram contexto. Documentar por que uma regra alerta em vez de remediar facilita revisar as premissas quando o contexto muda.
  • 💰Custo faz parte da decisão. O cenário VitaCore não contém estimativa financeira verificada; custos de AWS precisam ser estimados com premissas explícitas para cada ambiente.
